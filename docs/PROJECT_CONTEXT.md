# Mafia Online — Project Context

> Главный документ проекта. Содержит описание, архитектуру, технические решения, состояние разработки и историю изменений.

## 1. Описание проекта

Mafia Online — веб-платформа для игры в классическую «Мафию».

Основная концепция:
- Игра полностью проходит на сайте.
- Telegram-бот используется только для авторизации и отправки приглашений.
- На сайте пользователь видит список друзей и их онлайн-статус.
- Пользователь может пригласить друга в игровую комнату.
- Друг получает приглашение через Telegram-бота.
- После принятия приглашения пользователь переходит на сайт в игровую комнату.

## 3. Основные компоненты

### 3.1. Веб-сайт

Основной интерфейс игры.

Функциональность:
- Регистрация и авторизация.
- Профиль пользователя.
- Список друзей.
- Отображение друзей онлайн.
- Добавление и удаление друзей.
- Создание игровых комнат.
- Присоединение к комнатам.
- Приглашение друзей.
- Игровой процесс.
- Отображение ролей.
- Голосовой чат через LiveKit.
- Игровые настройки.

### 3.2. Telegram-бот

Бот не управляет игровым процессом.

Его задачи:
- Авторизация пользователя.
- Привязка Telegram-аккаунта к аккаунту сайта.
- Получение приглашений в игру.
- Отправка уведомлений.
- Кнопка перехода в игровую комнату.

### 3.3. Backend

Отвечает за:
- Пользователей.
- Авторизацию.
- Друзей.
- Онлайн-статусы.
- Игровые комнаты.
- Приглашения.
- Игровую логику.
- Роли игроков.
- Управление игровыми фазами.
- Интеграцию с LiveKit.

### 3.4. Голосовой чат

Используется LiveKit.

Требования:
- Создание голосовой комнаты.
- Подключение игроков.
- Управление микрофоном.
- Отключение микрофона.
- Контроль доступа.
- Работа во время игровых фаз согласно правилам игры.

## 4. Игровая механика

## 12. Стандарты Python и архитектура backend

### Типизация Python

1. Весь новый Python-код должен использовать Type Hints.
2. Каждая функция и каждый метод должны иметь типы аргументов и возвращаемого значения.
3. Не использовать `Any` без веской технической причины.
4. Использовать корректные типы Django и Django REST Framework.
5. Для QuerySet, моделей, сериализаторов и пользовательских структур данных указывать подходящие типы.
6. При изменении существующего кода постепенно добавлять типизацию.
7. Не усложнять код ради типизации.
8. Соблюдать единый стиль типизации во всех приложениях backend.
9. По возможности использовать статические анализаторы типов.

### Архитектура backend

- `models.py` — модели и структура данных.
- `serializers.py` — сериализация и валидация API.
- `views.py` — обработка HTTP-запросов и ответы.
- `services.py` — бизнес-логика и операции изменения данных.
- `selectors.py` — запросы и получение данных из БД.
- `permissions.py` — проверка прав доступа.
- `tests.py` — тестирование.

### Архитектурные требования

- Не размещать сложную бизнес-логику непосредственно во views.
- Не выносить простые операции в дополнительные слои без необходимости.
- Все изменения должны соответствовать существующей архитектуре проекта.
- Перед добавлением новых зависимостей проверять необходимость их использования.
